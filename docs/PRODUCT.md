## Product definition

AI_FACTORY_OS is not primarily:

- one AI Agent
- one code generator
- one prompt pack

It aims to become:

> an engineering system in which AI can participate in software evolution continuously, under control, with verification and traceable facts.

The goal is not merely “AI writes code faster.”

The goal is that software remains, even with deep AI participation:

- controllable
- verifiable
- traceable
- evolvable
- recoverable

## Product principles

### 1. Human-owned

Final goals, major decisions, risk acceptance, and final authorization belong to the Human Owner.

### 2. AI-assisted but not AI-governed

AI may analyze, propose, and implement.  
AI must not become the final governance authority.

### 3. Evidence-driven

Critical engineering and product judgments should eventually connect to facts and validation.

This phase states the principle only.  
**An Evidence System is not established yet.**

### 4. Continuously evolving

Both the product and the engineering system may evolve under controlled change.

### 5. Replaceable intelligence

AI providers, models, and agents are not irreplaceable system cores.  
See [AGENTS.md](../AGENTS.md).

## Product boundary

AI_FACTORY_OS is **not currently equal to**:

- an ordinary SaaS product
- an AI coding IDE
- a prompt manager
- a documentation CMS
- a plain Git workflow
- a collection of automation bots

Any of these may become part of the system later.  
None of them replaces the core product positioning above.

## Product success model

```text
System Capability
↓
Engineering Reliability
↓
Real-world Product Outcome
```

### System Capability

Can AI participate in engineering continuously inside explicit boundaries?

### Engineering Reliability

Can the system detect, block, locate, repair, and track failures?

### Real-world Product Outcome

Does the resulting product create real user value?

Hard distinction:

> A healthy engineering system is not the same as product success.

## Product evolution

Product direction itself may evolve.

Major product-direction changes must not be made by casually rewriting this file alone.  
They require a formal Product Decision mechanism.

**That Product Decision mechanism is not established in this phase.**  
This file only records the principle.
